## How to maintain these documents

- Read status and the relevant requirements before implementation.
- Update status after meaningful development work; record what changed and what was verified.
- Record consequential decisions with their date, rationale, and status. Preserve superseded decisions rather than silently rewriting history.
- Keep requirements in product scope, implementation boundaries in architecture, and acceptance criteria in milestones. Link between them instead of maintaining duplicate lists.
- Mark assumptions and proposals explicitly. A suggested feature or technology is not automatically an approved requirement.
- Mark a milestone complete only when its acceptance criteria have evidence. Separate simulated behavior from hardware-validated behavior.
- The user handles Git pulls and pushes.
