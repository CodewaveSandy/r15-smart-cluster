# Turn guidance v1 — normative firmware contract

Frozen for firmware-first implementation, 2026-11-05. This specifies the firmware bytes; Android is not implemented and real Google Maps notification feasibility/update cadence, actual MTU, latency and physical acceptance remain open. It replaces the proposals in the planning handoffs. Printable ASCII English profile only; unknowns never become directions. c011–c015 and R15G/P/N/M remain unchanged. c016–c01b remain absent.

## GATT and context

Under service `813b1240-8fd9-4d67-a53b-9f0a2531c010`: c01c READ capabilities, c01d WRITE WITH RESPONSE command, c01e READ/NOTIFY status. All require encrypted, authenticated Secure Connections, stored bond and16-byte key on the current one-phone connection. No write-without-response. Actual ATT MTU must be≥227 for guidance; request247 on Android using the existing ATT owner. Lower MTU does not disable legacy services. Reads reject nonzero offsets. Service Changed refreshes normal bonded discovery.

All multibyte integers little-endian. Real elapsed timestamps are1..2^63−1 ms (the explicit Unknown sentinel is separate). u32 Unknown=`0xffffffff`; u64 Unknown=`0xffffffffffffffff`. CRC32 ISO-HDLC covers all preceding bytes; final4 bytes little-endian. Every version/type/header/reserved/length/range/padding/context/CRC field is checked before state mutation. Command IDs boot/connection/display/stream and command sequences are nonzero. In inactive/capability/status responses, unavailable context and not-yet-consumed stream/sequence fields may be0; only matching nonzero context can establish readiness or ACK. Forward u32 order is delta in1..0x7fffffff; source revisions use the same rule independently. Sequence is global across streams within a secured connection, including Open. A new Open needs a distinct stream and forward sequence; Clear closes the stream and fences all delayed commands until a forward Open. Reconnect/board loss invalidates anchors, assemblies and live content. Byte-identical same-sequence retry returns the original consumption/publication state without renewing any age; conflicting retry is rejected. Last accepted command is retained only in RAM.

Common40-byte header plus body plus4-byte CRC; maximum224 bytes. Flags: Instruction1, Road2, Summary4, Maneuver8, NextDistance16, RemainingDistance32, RemainingTime64, Exit128, Truncated256, AgeKnown512; all other bits zero. Source cannot be in the future.

Same content revision fixes source state, maneuver, next distance, instruction, road, exit, their validity/truncation flags and original source-change time; optional summary/remaining fields can change without refreshing content age. A new revision cannot move a known source-change time backwards or duplicate identical meaningful core fields with only a changed timestamp/summary. Snapshot dispatch cannot move backwards within a stream. No UTC clock is involved.

## Timing and local expiry

Time anchor maps display DB to phone interval[T0,T1]. Conservative phone upper(now)=T1+(now−DB)+2+ceil((now−DB)/10000), accounting for100 ppm drift; lower uses T0 minus the same margin. Refreshing intervals must overlap the old clock bounds (including drift) while the old anchor is valid; a phone monotonic clock jump is rejected. Anchor expires at30,000 ms from DB, refresh target25,000 ms. Snapshot dispatch must not exceed upper(now), and upper(now)−dispatch must be<5000 ms. Source age upper=upper(now)−source-change; known source-change is not replaced by arrival time. Handshake and display acceptance do not refresh source content age.

Previously expired content is not redisplayed merely because its timing anchor becomes unknown. Snapshot/Presence renew transport receipt only; without one for5000 ms, withdraw all old fields and briefly show Link lost (3000 ms) then normal trip/info. Once lost, the stream closes and requires forward Open. Presence cannot revive lost data. Missing/expired clock or unknown source age shows neutral `Age unknown`, no arrow/distance/ETA. Source age≥30,000 ms uses `Last Maps update`, muted text/no action or ETA;≥120,000 ms shows only `Guidance update pending`. Presence can sustain that message without changing source time. Rerouting/GPS lost/paused/unsupported and replacement pending suppress old actions immediately. Arrival lasts at most5000 ms from its first accepted content revision, not from a retry/presence/summary update. Clear reasons remain reported in status; Stop restores ordinary trip/info immediately. Inactive state has no empty permanent card. Settings/warnings/lifecycle hide guidance without renewing source eligibility.

## R15W status (112 bytes)

0 magic;4 version1;5 type0;6 length112;7 flags: stream open1, clock valid2, dashboard model published4, directional action eligible8, transport live16, source age known32, diminished64, card enabled in current dashboard scene128.8 boot;12 connection;16 display;20 stream;24 consumed sequence;28 accepted revision (all u32).32 source state;33 view quality Inactive0/Waiting1/Fresh2/LastUpdate3/Pending4/UnknownAge5/Unsupported6/LinkLost7/Cleared8;34 rejection reason None0/Invalid1/Context2/Sequence3/Closed4/Clock5/Revision6/Busy7/Rate8;35 Clear reason (0 or1..6).36 source age upper u32 or Unknown.40 last consumed command receipt DB u64;48 dashboard-model publication DB u64;56 outstanding TimeRequest sequence u32;60 zero u32;64 echoed T0 u64;72 echoed DB u64;80 accepted source-change u64 or Unknown;88 last Snapshot/Presence receipt DB u64;96 last rejected command sequence u32;100 rejection counter u32;104 source-age-at-last-accept upper u32 or Unknown;108 CRC.

Status describes display consumption/publication, not vehicle admission. Published means Dashboard consumed the current model after acceptance; Visible separately distinguishes Settings/modal/warning/lifecycle hiding; it is software visibility, not an optical/panel scanout acknowledgement. Publication never advances source age. Failed commands retain consumed/accepted state and identify the rejected sequence/error separately. Status refresh500 ms, capability1000 ms; reads/notify coalesce latest, never accumulate turn history. Android waits for matching context/sequence and Snapshot publication before claiming Shared. ATT success only admits the command to the bridge. ACK timeout1 s, Status read fallback, at most2 identical retries, then Unavailable. Numeric diagnostics only, no instruction/road/notification text logs.

## UART framing and resource bounds

Legacy frames remain unchanged. R15Q frames are prefix + escaped raw bytes + zero delimiter. Raw header12: version1, direction1(vehicle→display)/2(reverse), sequence u16, inner total u16 (1..224), offset u16, payload length u8 (1..48),3 reserved zeros. Payload, then raw CRC32; raw size16+payload≤64. Escape0/0x52/0x7d as0x7d followed by byte XOR0x20. Maximum encoded record133. Generic transport knows no map or guidance model; adapters accept only U forward and F/W reverse. Reassembly is atomic, ≤500 ms from first fragment, exact contiguous offsets/current sequence/direction/total and byte-identical duplicate fragment handling. A newer offset0 replaces a partial record; no partial publication. Retired map inner types never reach a guidance store.

One nonblocking TX worker per UART preserves critical G/P/N/M priority. Guidance latest mailbox + Clear preemption between whole fragments; ≤1536 encoded bytes/s with max133-byte burst. Forward Snapshot admission≤2/s, Presence≤1/2s; identical retry is not new content and preserves freshness. One outstanding ACK barrier; the phone retains its latest coalesced snapshot until that barrier completes, and vehicle admission returns Busy meanwhile. Clear may supersede it. Fixed guidance allocations compile-time bounded≤4 KiB per MCU, excluding existing driver/task/LVGL/font storage. No map arenas, PSRAM objects, disk caches, notification history or new RTOS owner.

Static normative vectors accompany this document; they are non-executable data, not an automated suite. Firmware/host builds and manual preview evidence are recorded in the firmware handoff. All target-phone and physical-board acceptance remains explicit.
